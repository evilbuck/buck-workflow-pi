# Recover a blocked `/buck-loop` run

Use the saved run's cause to repair the interruption without skipping safety checks.

## Steps

1. Run `/buck-loop --status` in the affected repository. Read the blocker and the recovery command in the result. A stopped run says `Run stopped` and labels its previous blocker as historical.
2. Fix the named cause. If the refusal names unstaged paths, those paths are outside the phase's `files:` list: preserve unrelated work separately; do not stage it merely to bypass the guard. The next commit checkpoint stages `.context/` and declared phase files itself. For a committing or blocked run with `Retained commit checkpoint`, status names the original target, baseline, and whether the checkpoint is uncommitted or an existing commit is verified. Run `/buck-loop --resume` only after inspecting the staged changes and confirming that target; an unchanged baseline resumes that phase's commit, while an already-created clean direct-child commit is verified without another `/b-commit`. Advanced HEAD with remaining dirt, divergent history, or failed Git queries authorizes no new commit: inspect and resolve the conflict first. Stopped runs use the manual sequence in step 3 instead.
   If status reports a missing or inconsistent checkpoint marker, do not resume into another build and do not infer the target from completed phase status or commit prose. Review the exact phase diff and complete its commit manually; then explicitly start the intended next phase. Unrelated unstaged paths remain refused.
   For `unphased plan remains open`, verify each named criterion directly and mark only proven entries `[x]` under the plan's `## Acceptance criteria`. Uppercase `[X]` is not checked. If the plan has no acceptance list, record `status: completed` only with completion evidence. Commit the intended acceptance evidence and leave the worktree clean; check that the saved run already contains a committing checkpoint.
3. For recoverable `blocked` runs that offer `/buck-loop --resume`, run that command. After a stop (`aborted`) with a retained commit checkpoint, resume will not continue it: inspect HEAD and staged changes, verify or complete that exact commit manually, then explicitly start the intended next phase. Do not replace the saved run before resolving its checkpoint. Only stopped runs without an outstanding checkpoint use the exact `/buck-loop <phase-or-plan-path>` shown by status. A new safety refusal must be resolved, not bypassed.
4. **Eat:** `/buck-loop --status` no longer reports the original blocker: the run has continued or reports a new, specific cause and recovery path. An eligible unphased closeout repair reports `done`, the subject is completed, and no build runs. Open criteria or lifecycle refusal remain blocked with their evidence named.
