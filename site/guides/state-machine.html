01

Prepare your kitchen

This recipe uses the portable module in the Buck Workflow source repository, not a globally installed CLI. You need basic TypeScript familiarity, a text editor, and a Bash-compatible terminal on Linux, macOS, or Windows through WSL.

  1. Install Git and Node.js 22 or newer. Node includes npm. If you use WSL, install them inside WSL.
  2. Check that these commands print version numbers:
Terminal · check your tools
bash
git --version
node --version
npm --version

If you do not have a checkout: clone the source. Otherwise open a terminal at its root—the directory containing package.json and extensions/.

Terminal · obtain the source
bash
git clone --branch master https://github.com/evilbuck/buck-workflow-pi.git
cd buck-workflow-pi

Confirm the module is present, install the locked toolchain, and create the example folder. npm ci provides TypeScript and tsx; you do not need Bun, an agent runtime, or an API key.

Terminal · run from the repository root
bash
test -f extensions/state_machine/index.ts && echo "Module source found"
npm ci
mkdir -p examples

Stop if a command fails. The first command must print Module source found. In an existing checkout, npm ci replaces installed dependencies with the lockfile versions. Use a separate clone if you need to preserve a customized dependency tree.

02

Sketch the workflow

The happy path has four states. An operator submits a draft; the caller chooses approval or revision; an approved article publishes automatically. Publication writes a local text file, not a website.

draftManual submit; at least ten words
reviewChoose approval or return to draft
approvedOne automatic publish target
publishedFinal; no outgoing targets

A manual STOP from draft, review, or approved goes to a fifth state, cancelled. It is never an automatic option.

  • Definition: the static graph, validated once.
  • Instance: one run’s current state. Start a fresh run or restore a persisted name.
  • Facts: caller-owned data about the world, supplied again on each evaluation.
  • Effects: descriptions returned as data. The caller performs the work.

The caller chooses routing policy. available(facts) can return zero, one, or many targets. The module neither picks the first nor rejects ambiguity. This recipe explicitly chooses in review and requires exactly one target for its automatic publish tick.

03

Define the machine

Create examples/article-machine.ts and paste the entire block. The two generic types describe facts and effect data; state names are inferred from the states keys.

examples/article-machine.ts
typescript
import { defineMachine } from "../extensions/state_machine/index.js";

export type ArticleFacts = {
  title: string;
  body: string;
  reviewerAvailable: boolean;
};

export type ArticleEffect =
  | { kind: "submit"; title: string }
  | { kind: "publish"; title: string; body: string };

export const articleMachine = defineMachine<ArticleFacts, ArticleEffect>()({
  initial: "draft",
  states: {
    draft: {
      targets: [
        {
          name: "review",
          manual: true,
          guard: (facts) => facts.body.trim().split(/\s+/).length >= 10,
          effect: (facts) => ({ kind: "submit", title: facts.title }),
        },
        { name: "cancelled", manual: true },
      ],
    },
    review: {
      targets: [
        { name: "approved", guard: (facts) => facts.reviewerAvailable },
        { name: "draft", guard: (facts) => facts.reviewerAvailable },
        { name: "cancelled", manual: true },
      ],
    },
    approved: {
      targets: [
        {
          name: "published",
          effect: (facts) => ({
            kind: "publish",
            title: facts.title,
            body: facts.body,
          }),
        },
        { name: "cancelled", manual: true },
      ],
    },
    published: { final: true, targets: [] },
    cancelled: { final: true, targets: [] },
  },
});

Definition and instance

MemberMeaning
defineMachine<Facts, Effect>()(config)Validates the graph once and returns a definition with no current state. Omit the generic types for a machine needing no facts or effects.
initialExactly one declared state; start() begins here.
statesThe keyed graph. TypeScript rejects a misspelled initial or target state.
definition.start()Creates a fresh instance. Other instances do not move when this one moves.
definition.restore(name)Validates an untrusted string and creates an instance there. No guards, effects, or transitions are replayed.
definition.targets(state)All declared destinations, including manual and currently guarded-out edges.
definition.isFinal(state)Whether that declared state permits the run to end.
definition.edge(from, to)The edge’s guard, effect, and manual flag. A missing edge throws IllegalTransitionError.

State properties

PropertyMeaning
targets (required)An array of outgoing edges. Use [] only for a final state; a non-final state with no targets is rejected as stuck.
final: true (optional)The run may legally end here. It may still have outgoing targets, and the initial state may also be final. Final does not forbid a move.

Edge properties

PropertyMeaning
name (required)A declared destination. There is at most one edge per source/destination pair.
guard (optional)Pure, synchronous (facts) => boolean. True permits the move; no guard means allowed. It is checked again during every transition.
effect (optional)Pure, synchronous (facts) => Effect describing work as data. It is evaluated only during a successful transition, not by available().
manual: true (optional)Operator-only: excluded from available(). An explicit transition(name, facts) can take it, but still checks its guard.

Definition validation rejects undeclared destinations, duplicate edges, unreachable states, stuck non-final states, and graphs with no final state. Reachability follows the static graph—including manual edges—without running guards.

04

Write the caller

Create examples/run-article-machine.ts with this complete program. It supplies facts, names the manual submit edge, chooses approval, enforces one automatic publish target, and writes the returned effect.

examples/run-article-machine.ts
typescript
import { writeFileSync } from "node:fs";
import {
  articleMachine,
  type ArticleFacts,
  type ArticleEffect,
} from "./article-machine.js";

const facts: ArticleFacts = {
  title: "A small state machine",
  body: "A state machine makes the next legal step explicit. The caller supplies current facts, chooses from declared options, and performs effects only after the machine returns a valid transition.",
  reviewerAvailable: true,
};
const run = articleMachine.start();

function interpret(effect: ArticleEffect | undefined): void {
  if (!effect) return;
  switch (effect.kind) {
    case "submit":
      console.log("Submitted for review: " + effect.title);
      break;
    case "publish":
      writeFileSync(
        new URL("./published-article.txt", import.meta.url),
        effect.title + "\n\n" + effect.body + "\n",
        "utf8",
      );
      console.log("Published to examples/published-article.txt");
      break;
  }
}

console.log("State: " + run.state);
console.log("Automatic before submit: " + (run.available(facts).join(", ") || "<none>"));
// An operator's submit handler names the manual edge explicitly.
interpret(run.transition("review", facts).effect);
console.log("State: " + run.state);

console.log("Choices: " + run.available(facts).join(", "));
// The caller chooses approval; the module does not resolve multiple targets.
interpret(run.transition("approved", facts).effect);
console.log("State: " + run.state);

// This caller's automatic tick requires exactly one available target.
const targets = run.available(facts);
const [target] = targets;
if (targets.length !== 1 || target === undefined) {
  throw new Error("Expected exactly one automatic target");
}
interpret(run.transition(target, facts).effect);
console.log("State: " + run.state);
console.log("Final: " + run.isFinal);

// Persist a state name in a real application, then restore on the next tick.
const restored = articleMachine.restore(run.state);
console.log("Restored: " + restored.state);

Instance methods and state

MemberBehavior
instance.stateThe current state name, owned by this instance rather than by facts.
instance.isFinalWhether the run may end here. Zero available targets alone does not prove completion.
instance.available(facts)Non-manual, guard-passing targets in declaration order. Does not move state or evaluate effects.
instance.transition(to, facts)Checks the edge, evaluates its guard, describes its effect, then moves state. Rechecks current facts even if to came from an earlier available() call.

A facts-less definition uses available() and transition(to). This article machine requires facts for both.

Transition result

The result is { from, to, effect }. Approval returns the following object; a transition without an effect still includes effect: undefined:

Transition · approval
typescript
{ from: "review", to: "approved", effect: undefined }

Movement and work are separate. A rejected edge, rejected guard, or throwing guard/effect function leaves state unchanged. After a successful transition, the instance has already moved before your interpreter runs. The caller owns persistence, asynchronous work, retries, and recovery if that work fails.

For durable loops, persist the state name at your chosen checkpoint and restore it on the next tick. Rebuild facts from the world; the module neither stores facts nor persists state for you.

06

Check the safety rails

Create examples/check-article-machine.ts. These complete checks exercise missing edges, guard rejection with unchanged state, multiple and zero automatic targets, manual STOP, restore validation, invalid graphs, and movement out of a final state.

examples/check-article-machine.ts
typescript
import assert from "node:assert/strict";
import {
  defineMachine,
  IllegalTransitionError,
  InvalidMachineError,
  UnknownStateError,
} from "../extensions/state_machine/index.js";
import { articleMachine, type ArticleFacts } from "./article-machine.js";

const facts: ArticleFacts = {
  title: "Safety check",
  body: "This article has enough words to pass the submission guard.",
  reviewerAvailable: true,
};
const run = articleMachine.start();
assert.deepEqual(run.available(facts), []);

assert.throws(
  () => run.transition("published", facts),
  (error) => error instanceof IllegalTransitionError && error.reason === "not-a-target",
);
assert.equal(run.state, "draft");
console.log("Rejected as expected: not-a-target");

assert.throws(
  () => run.transition("review", { ...facts, body: "Too short." }),
  (error) => error instanceof IllegalTransitionError && error.reason === "guard-rejected",
);
assert.equal(run.state, "draft");
console.log("Rejected as expected: guard-rejected");

run.transition("review", facts);
assert.deepEqual(run.available(facts), ["approved", "draft"]);
console.log("Automatic choices: " + run.available(facts).join(", "));
const blocked = { ...facts, reviewerAvailable: false };
assert.deepEqual(run.available(blocked), []);
assert.equal(run.isFinal, false);
assert.throws(
  () => run.transition("approved", blocked),
  (error) => error instanceof IllegalTransitionError && error.reason === "guard-rejected",
);
assert.equal(run.state, "review");
console.log("Unavailable reviewer: no automatic route");

// STOP is not offered automatically, but its explicit transition is legal.
run.transition("cancelled", facts);
assert.equal(run.isFinal, true);
console.log("Manual cancellation: " + run.state + " (final)");

assert.throws(() => articleMachine.restore("missing"), UnknownStateError);
console.log("Rejected as expected: unknown state");
assert.throws(
  () => defineMachine()({ initial: "draft", states: { draft: { targets: [] } } }),
  InvalidMachineError,
);
console.log("Rejected as expected: invalid graph");

// Final means the run may end here, not that every move is forbidden.
const transmission = defineMachine()({
  initial: "park",
  states: {
    park: { final: true, targets: [{ name: "drive" }] },
    drive: { targets: [{ name: "park" }] },
  },
}).start();
assert.equal(transmission.isFinal, true);
transmission.transition("drive");
assert.equal(transmission.isFinal, false);
console.log("Final states can still move: park -> " + transmission.state);

Rejected as expected: guard-rejected

Error classes

ErrorWhenDetails
InvalidMachineErrorGraph validation fails during definition.problems: validation problems.
UnknownStateErrorrestore() receives an undeclared name.state: the supplied string.
IllegalTransitionErrorNo edge exists, or its guard rejects the move.from, to, reason: "not-a-target" or "guard-rejected".

Errors thrown by your guard or effect function propagate unchanged. Catch the error classes or inspect their structured details rather than matching message text.

Lift it into your own project

  1. Copy extensions/state_machine/ as-is and update your import path. Its index.ts has no imports or runtime dependencies; the folder’s behavior tests use Vitest only as a development dependency.
  2. Replace facts, effect data, and the state graph. Keep guards and effect descriptions pure and synchronous. Declare every target and a legal final state.
  3. Choose a zero/one/many routing policy in your caller. Mark START, STOP, and resume edges manual: true; explicit moves still honor guards.
  4. Keep I/O, model calls, retries, clocks, persistence, and effect execution outside the module. Test the new routes and failure boundaries.

If something goes wrong

SymptomWhat to check
Missing module or compilerReturn to the checkout root, confirm extensions/state_machine/index.ts exists, and complete npm ci. Do not install a separate package named tsc.
No automatic target in draftSubmit explicitly with transition("review", facts). Manual edges are intentionally hidden from available().
guard-rejectedSubmission requires ten words; approval/revision require an available reviewer. Refresh facts instead of reusing a stale option.
Zero or multiple targetsThe caller must wait, choose, or fail according to its policy. Zero does not mean final; inspect isFinal.
Publication write failsThe output is beside the runner. Check filesystem permissions. The instance has already moved; recovery is caller-owned.
