# pack-self-contained-html-reports

Combine N already-built self-contained tabbed HTML reports into **one** Chrome-openable `file://` file. Each report becomes one `.docapp` panel inside the pack; the pack adds a sticky docbar with switcher buttons and an in-page hash router that scopes every link to the active report.

Sibling of `markdown-docs-to-tabbed-html`: that skill **builds** a tabbed doc-app; **this** skill **packs** two or more of those (or any same-shape `.tab` / `#panel-X` / `.tocgroup` HTML) into one file because merging 11 tabs overflows the strip. Do not merge tab strips.

## When to use

- User asks to combine sidecar HTML reports into one Chrome pack.
- User edited a packed source report and needs a rebuild.
- User added a report to `pack.config.mjs` and wants the pack refreshed.
- User wants to email / drop a single-file view onto another machine (no server, no network).
- User wants one reader that knows all sibling cross-links and stays in sync across views.

Do **not** use for a single tabbed report — that's `markdown-docs-to-tabbed-html`.

## Procedure

1. **Resolve the report directory.** User gives an explicit path → use it. Otherwise walk up from cwd for the nearest `pack.config.mjs`. If none, offer to create one (next step).
2. **If no config exists**, copy `assets/pack.config.example.mjs` to `<dir>/pack.config.mjs` and fill `reports[]` from the HTML files the user named. Do **not** invent a third report. Each entry needs `key`, `file`, `label`, `title`. `tone` is optional ("primary" default, or "ref").
3. **Do not edit source report HTML** as part of packing. Do **not** hand-edit the generated pack. The pack banner is: `<!-- generated by pack-self-contained-html-reports — do not edit; add a report in pack.config.mjs and re-run the skill -->`.
4. **Rebuild:**
   ```
   bun "${SKILL_DIR}/scripts/pack.mjs" --dir <report-dir>
   ```
   Where `SKILL_DIR` is the directory holding `SKILL.md` (canonical: `${BUCK_WORKFLOW_ROOT:-$HOME/projects/development_tools/buck-workflow-pi}/skills/pack-self-contained-html-reports`).
5. **If the user added a report**, append one object to `reports` (unique `key` + `file`), then re-run the same command. The static gate will catch duplicate keys, dead anchors, leftover sibling `.html` hrefs, `<script src`, `<link rel=stylesheet`, and `fetch()` calls.
6. **Verify:**
   - `bun pack.mjs --dir <dir>` exit 0 is the static gate.
   - JSON output: `out`, `bytes`, `kb`, `idCollisions`, `tabKeyCollisions`, `mainRenames`, `deadAnchorCount`, `leftoverHtmlHrefs`. Each must be empty or explained.
   - If the user wants Chrome/`file://` confirmation, headless-check deep links across reports (do **not** `page.click` the first `a[href="#id"]` — hidden copies exist; click the visible one in the active `.docapp`).
   - If `puppeteer` is not importable, say so and rely on the static check; do not fake Chrome results.
7. **Tell the user:**
   - File → Open the generated file in Chrome, or drag it onto a window.
   - Rebuild command (step 4).
   - How to add another report (edit `pack.config.mjs`, re-run).

## What the script does (so you can explain it)

1. Reads `pack.config.mjs` from `--dir DIR` (default `cwd`) or `--config PATH`. Paths in the config resolve relative to the config's directory.
2. Loads each report's `<body>` and dedupes `<style>` chunks by SKILL theme convention (`/* ---- header ---- */`), so two reports that ship the same theme contribute the CSS only once.
3. Detects two collision kinds:
   - **id collision** — same `id="X"` in 2+ reports. First report keeps bare; later reports prefix `{key}-X`. `main` is special: any report with `id="main"` renames it to `main-{key}` (so two visible skip-link targets never share `id="main"`).
   - **tab-key collision** — same `data-tab="X"` in 2+ reports. First keeps bare; later prefixes and renames the related DOM ids (`tab-X` → `tab-{key}-X`, `panel-X` → `panel-{key}-X`). `data-tab`/`data-toc` values stay semantic; app.js's scoped lookup (`root.querySelector("#panel-" + k)`) makes the rename transparent.
4. Rewrites cross-file `href="other.html#frag"` → `href="#frag"` (or `#doc-{key}` for bare filename) **only** for relative sibling paths whose basename is a packed report. Absolute, schemed (`https://`, `file:///`), protocol-relative (`//cdn`), and `/abs/...` hrefs are not touched.
5. Strips inlined `<script>` and `<style>` from each body (the pack injects its own).
6. Assembles one `<style>` (CSS chunks + `assets/extra.css`), a `<nav class="docbar">` with switcher buttons, N `<div class="docapp" data-doc="..." data-tone="..." id="doc-..." hidden?>` blocks, and one `<script>` (`assets/app.js`).
7. Writes `<config.out>`. If `config.index` exists and contains an `<a class="rcard" href="...">...</a>` with a `<b>N</b> KB` chip, updates that chip to the new byte count.
8. Runs the static gate. Prints JSON summary; exits non-zero on any failure.

## Tests

`scripts/pack.test.mjs` runs under `bun:test`. Synthetic two-file fixtures in `os.tmpdir()` cover:

- sibling `href="other.html#frag"` → `#frag` (and bare file → `#doc-{key}`)
- colliding `id="x"` prefixed in the later report
- colliding tab key `ov` prefixes later report's `tab-ov`/`panel-ov`/`aria-controls`/`aria-labelledby`
- `id="main"` always becomes `main-{key}` in every report that has it
- no leftover sibling `.html` hrefs among packed filenames
- relative rewrite does **not** touch `https://`, `file:///`, `//cdn`, `/abs/...`
- missing `tone` defaults to `data-tone="primary"`

Run from the skill directory:

```
cd skills/pack-self-contained-html-reports && bun test
```
