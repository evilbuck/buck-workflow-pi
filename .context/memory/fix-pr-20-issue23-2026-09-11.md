## Issue #23 blockers fixed (option a: wire the machine)

1. **executeRun never drove the machine.** Rewrote `extensions/b-save/index.ts`:
   `executeRun` now drives snapshot → roles → evaluate → apply → effects through the
   XState actor (`SNAPSHOT_DONE`/`EVAL_DONE`/`APPLY_DONE`/`EFFECTS_DONE`), and
   `manifestFor` persists real contents (session_evidence, input_hashes, 3 role
   proposals, patch_set, journal mirrored from the apply journal).
   - Phase decomposition for the complexity gate (CCN ≤ 10): `takeSnapshotPhase`,
     `runRolesPhase`, `evaluatePhase`, `resumeRun`, `recoverJournalIfAny`,
     `manifestSubject`. `executeRun` CCN 20 → within limit; zero lizard warnings.
   - `machine.ts`: root-level `MODEL_FAILED` → `failed_model` (roles fail while
     `evaluating`, which had no MODEL_FAILED transition).
   - `types.ts`: manifest journal statuses now the real apply statuses
     (`idle|in-progress|completed|rolled-back`) instead of cosmetic words.
   - `evaluate.ts`: `EvalInput.subjectResolved` — `ruleSubject` no longer re-trips
     the ambiguity gate after `--subject` answered it (was a resume deadlock).
2. **continueFrom mishandled non-terminal resumes.** Still-waiting resumes without
   the required flag are now report-only (no effects, no manifest rewrite) via a
   `WAITING_FLAG` table; `failed_apply` resume runs `recoverApply(resume)` when a
   journal exists and then continues the full pipeline through effects, reporting
   the actual terminal state. Before-image drift keeps the run `failed_apply` with
   the error visible.
