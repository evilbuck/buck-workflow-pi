### Child-session isolation and real SDK
- `extensions/buck-loop/run-step.ts:135-144,393-415` creates in-memory restricted child sessions: `disableExtensionDiscovery: true`, `restrictToolNames: true`, `enableMCP: false`, built-in-only tool allowlists. `sql_memory` is registered in the parent `extensions/index.ts:14,31` only when `SQL_MEMORY_URL` is set (`extensions/sql-memory/index.ts:55-64`). Merely naming `sql_memory` in a skill will fail inside `/buck-loop`.
- OMP SDK docs at pinned `can1357/oh-my-pi@33f887a` confirm: restricted child extension tools cannot expand tool set; SDK-provided `customTools` require both `allowRestrictedCustomTools: true` and name in `toolNames`. The plan needs an intentional injection of the existing `sqlMemoryTool(...)` contract into selected child sessions, or a supervised tool-call seam with equivalent exact behavior. No reopening ambient extension discovery and no new direct-SQL path inside portable skills.
